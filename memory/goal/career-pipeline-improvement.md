# Goal — 취업 파이프라인 구조 개선 분석

## 목표

공고 분석, 지원자 사실 원장, 자격 판정, 공식 자료조사, NRS 자기소개서 작성, 면접 대비, 감사·회귀평가를 하나의 추적 가능한 운영 경로로 수렴시키기 위한 구조 개선안을 확정한다.

## 완료 정의

- 현재 구현과 실제 사용 상태를 분리해 기록한다.
- 전체 파이프라인을 상호 배타적인 6개 영역으로 나누고, 각 영역의 입력·출력·검증·운영 병목을 확인한다.
- 과거 실행 표본을 통해 기능 존재 여부가 아니라 실제 채택 여부를 확인한다.
- 우선순위, 구현 단위, 완료 기준, 보류 범위를 명시한 개선 보고서를 남긴다.
- 다음 구현 작업이 사용자 추가 해석 없이 시작될 정도로 범위를 좁힌다.

## 검증 표기

- `확인됨`: 둘 이상의 독립된 직접 근거가 일치한 경우
- `관찰됨`: 현재 체크아웃의 코드, 테스트 또는 로컬 실행 기록에서 직접 확인한 경우
- `가정`: 진행을 위한 보수적 해석
- `미확인`: 추가 실행 또는 사용자 입력이 필요한 경우

## 다음 한 단위

**P0 운영 수렴 패키지**를 구현한다.

1. 기본 CLI의 `workflow start/resume/status`에 골든패스 진입점을 연결한다.
2. 기존 실행을 변경하지 않고 새 계약 준비도와 누락 산출물을 보여주는 `migrate-plan` 진단을 추가한다.
3. 최초 실제 NRS 스모크 런 전에 공고·프로필·연구·면접 단계별 사람이 해야 할 작업을 한 상태 문서에 모은다.

이 단위는 새 작성 알고리즘보다 먼저 수행한다. 현재 가장 큰 실패는 생성 품질이 아니라 구현된 경로가 실제 실행에 쓰이지 않는 점이기 때문이다.

구체적인 CLI 인자, 출력 스키마, 종료 코드, 레거시 준비도 판정, 벤치마크 모드와 신규 테스트 계약은 `docs/2026-08-30-career-pipeline-improvement-analysis.md`의 “1단계 구현 계약”을 따른다.

## 보류·폐기한 경로

- 2026-08-17 문서의 “골든패스가 없다”, “면접지능이 없다”는 지적은 현재 코드에서는 해소되어 그대로 반복하지 않는다.
- NRS를 다시 실험 기능으로 되돌리지 않는다. 사용자 승인과 holdout 통과에 따라 기본값을 유지한다.
- 합격 확률 추정은 목표에 포함하지 않는다. 사용자 선호와 면접 수행 평가는 품질 개선 신호로만 사용한다.
- 기존 실행 폴더와 사용자 자료를 일괄 변환하거나 덮어쓰지 않는다.

## 근거 한계

- 과거 실행 68건은 한 사용자의 2026년 7~8월 로컬 기록이며 일반적인 채용 성과를 대표하지 않는다.
- 로컬 코드 사실은 단일 체크아웃에서 관찰한 상태다. 원격 저장소 또는 다른 브랜치와의 일치 여부는 이 분석에서 확인하지 않았다.
- 실제 새 공고를 대상으로 한 NRS 기본 작성기의 production 실행은 아직 없다.
