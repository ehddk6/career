# 자기소개서 반복 탈락 방지 프로젝트 개선 프롬프트

## 실행 프롬프트

당신은 `career_pipeline`의 품질·검증 책임자다. 자기소개서 제출 후 반복 탈락이 발생하는 상황을 “합격 보장”으로 포장하지 말고, 실제 전형 결과와 현재 실행 산출물을 근거로 예방 가능한 탈락 위험과 잘못된 제출 준비 판정(false-ready)을 줄이도록 프로젝트를 개선하라.

### 목표

1. 과거 탈락·진출 결과를 원문이나 개인정보 없이 구조화하고, 공식 피드백과 추정 원인을 구분한다.
2. 확정된 피드백을 다음 자기소개서의 문항전략·후보 생성·독립 심사에 연결한다.
3. 상대평가에서 가장 높은 후보라도 절대 품질 하한이나 미해결 검토 조건을 충족하지 못하면 `passed/ready`로 표시하지 않는다.
4. 내부 총점이 높더라도 문항별 품질, 권장 분량, 사람 검토, 엄격 선발 중 하나가 미완료면 제출 준비 상태를 보류한다.

### 입력과 출처 우선순위

1. 공식 전형 피드백 및 사용자가 보존한 결과 기록
2. `docs/*rejection-analysis*.md`의 확인된 사실과 명시적으로 표시된 개선 가설
3. `career_runs/**/run.json`, `07_글자수검증.json`, `11_최종품질감사.json`, `12_최종산출물.json`의 상태·경고·해시
4. 현재 코드, 테스트, 사용 문서

자기소개서 원문, 개인식별정보, 자격·경력의 미확정 값은 결과 피드백 원장이나 모델 프롬프트에 복사하지 않는다. 공식 피드백은 `confirmed/official`, 문서 비교에서 도출한 가설은 `proposed/inferred`로 분리한다. 내부 점수는 합격 확률로 해석하지 않는다.

### 성공 기준

- 결과 원장의 스키마·출처·경로·중복·확정 상태를 결정적으로 검증할 수 있다.
- V2 `prepare`가 관련 결과를 별도 감사 산출물과 `05_문항전략.json`에 주입한다.
- 확정된 hard 피드백 요구는 후보 검증에서 실제로 차단되고, 추정 또는 교차기관 신호는 의미 검토 대상으로 남는다.
- rigorous 우승 후보가 다음 내부 하한을 모두 만족할 때만 `passed`다: 심사 중앙값 85 이상, 최저 심사점 70 이상, 핵심 점수 중앙값 28 이상, 미해결 `REVIEW_REQUIRED` 없음.
- 제출 준비 판정은 문항별 최소 85점, 전체 평균 90점, 권장 분량 PASS, `human_review_recommended=false`, rigorous 절대 하한 PASS를 모두 요구한다.
- `audit` 명령은 총점이 높아도 품질 게이트 실패 또는 사람 검토가 남으면 성공 종료코드를 반환하지 않는다.
- 새 적대적 회귀 테스트와 기존 전체 테스트가 통과한다.

### 제약과 판단 규칙

- 현재 작업트리의 사용자 변경을 보존하고, 요청과 무관한 리팩터링을 하지 않는다.
- 기존에 반영된 `weak_observable_result`, `missing_duty_or_competency_match`, 문체·반복 규칙을 중복 구현하지 않는다.
- 과거 한 건의 탈락을 모든 기관의 확정 원인으로 일반화하지 않는다. 동일 기관의 공식·확정 약점 또는 공식 약점이 두 사례 이상 반복된 경우만 hard 요구가 될 수 있다.
- 외부 전송, 실제 원서 입력·제출, 브라우저 자동화, 개인정보 이동을 수행하지 않는다.
- 검증하지 않은 결과를 완료로 보고하지 않는다.

### 실행 절차

1. 저장소 상태와 기존 변경을 확인하고 전체 테스트 기준선을 기록한다.
2. 탈락 분석 문서와 최근 실행 산출물을 메타데이터 수준에서 감사해 반복 위험을 찾는다.
3. 결과 피드백 원장, CLI, 문항전략 연결, rigorous 절대 하한, 제출 준비 fail-close를 최소 범위로 구현한다.
4. 정상 입력, 미확정 피드백, 잘못된 원장, 전원 0점·검토 필요 심사, 낮은 문항점수, 권장 분량 미달을 테스트한다.
5. 관련 테스트와 전체 테스트를 실행한다.
6. 변경 파일, 검증 결과, 남은 한계와 실제 사용 명령을 보고한다.

### 출력

- 실행 프롬프트 파일
- 코드·테스트·사용 문서 변경
- 로컬 결과 피드백 원장 또는, 자동 추출이면 사용자 확인 전 `proposed` 원장
- 검증 명령과 실제 결과
- 합격을 보장하지 않는다는 한계 및 남은 사람 검토 항목

### 중단 조건

개인정보 원문을 결과 원장에 넣어야 하거나, 실제 지원·외부 전송이 필요하거나, 기존 사용자 변경을 안전하게 보존할 수 없으면 해당 작업을 중단하고 이유를 보고한다. 테스트 실패가 남으면 완료로 표시하지 않는다.
